# Screenshot captures

## What’s in this folder

These images are generated from the built-in screenshot harness used during UI testing.

- `01-overview.png` — overview state used in the main menu/status badge
- `02-rules.png` — rules/trust panel
- `03-risk-yellow.png` — medium-risk simulated alert
- `04-risk-red.png` — high-risk simulated alert
- `05-permissions.png` — permission guidance card

The harness is powered by `II_SCREENSHOT_FIXTURE` scenarios and writes PNG files into
`II_SCREENSHOT_OUTPUT_DIR` during launch mode.

## How to recapture (from this repo)

These captures are generated by launching the built app in capture mode.

For reproducible local output:

```bash
for fixture in healthy yellow red permissions; do
  II_SCREENSHOT_CAPTURE=1 \
  II_SCREENSHOT_FIXTURE=$fixture \
  II_SCREENSHOT_OUTPUT_DIR="$(pwd)/docs/screenshots" \
  II_SCREENSHOT_NAME="$(case "$fixture" in healthy) echo 01-overview.png;; yellow) echo 03-risk-yellow.png;; red) echo 04-risk-red.png;; permissions) echo 05-permissions.png;; esac)" \
  II_SCREENSHOT_CAPTURE_RULES=$([[ "$fixture" == healthy ]] && echo 1 || echo 0) \
  build/Build/Products/Debug/IntrusionIndicator.app/Contents/MacOS/IntrusionIndicator
done
```

## Capture notes

- Run captures on the same macOS appearance/lightness settings used for this guide.
- Keep menu bar extra hidden if you need a clean menu-style frame.
- Rebuild the app before capture if rule/severity wording or alert copy changes.
- Keep screenshots in PNG, 1024px+ width for clean GitHub rendering in the README.
